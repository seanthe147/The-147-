Data Breach Response Procedure
UK GDPR Article 33 — reportable breaches must be notified to the ICO within 72 hours. Follow these steps immediately if a breach is suspected.
Step 1
Contain
Stop the breach. Change compromised passwords, revoke API keys, restrict access. Do not delete evidence.
Step 2
Assess (within 24hrs)
Identify: what data was exposed, how many people affected, likely risk to individuals. Document everything with timestamps.
Step 3
Report to ICO (within 72hrs if high-risk)
If the breach is likely to result in a risk to individuals' rights or freedoms, report via ico.org.uk/for-organisations/report-a-breach/
Step 4
Notify Affected Individuals
If the breach poses a high risk to individuals, contact them directly without undue delay. Be clear about what happened and what they should do.

Data Backup
A snapshot of all bookings, orders, memberships, and customer accounts is saved automatically every night. The last 5 daily backups are kept — when a 6th is created the oldest is removed automatically. Backups are stored as separate files completely independent of the live database, so deleting or changing data in the app has no effect on them.
To restore data: Click Restore next to any backup below, choose which table to recover, and confirm. The live data for that table is replaced with the snapshot — any changes made after that backup was taken will be lost.

Offline copies: Use the Download link to save a file to your phone, USB drive, or Google Drive. If you ever need to recover from a downloaded file, share it with your developer — they can restore from it directly.
