---
name: Prize code redemption
description: Two separate code systems (game prizes + venue rewards) had mismatched normalization and alphabets causing staff to get "not found" on valid codes.
---

## Two code systems

1. **Game prize codes** (`game_plays.prize_claim_code`) — generated by `generateClaimCode()` in `routes.ts`
2. **Venue reward claim codes** (`venue_reward_claims.claim_code`) — generated inline in `storage.createVenueRewardClaim()`

Both now use the same alphabet: `"ACDEFGHJKLMNPQRTUVWXY234679"` — no confusable chars (0/O, 1/I, 5/S, 8/B).

## Normalisation rule

Any code lookup must run: `.toUpperCase().trim().replace(/[^A-Z0-9]/g, "")` before the DB query. This strips leading `#`, dashes, spaces that customers copy-paste from the display.

- `redeemGamePlayByCode` in `storage.ts` — already did this correctly
- `getVenueRewardClaimByCode` — was missing the `replace()` step (fixed)

## Error types

`redeemGamePlayByCode` now throws `{ alreadyClaimed: true }` (instead of returning `null`) when the code exists but is already claimed. Callers return HTTP 409. Staff dashboard shows a yellow warning ("already redeemed") vs red error ("not found") — these are different staff actions.

## "Pending Prizes" bypass

Staff can bypass code entry entirely via the **Pending Prizes** table in the Loyalty Game panel. It calls `/api/staff/game/pending-claims` and shows a "Mark Claimed" button per row → `POST /api/staff/game/plays/:id/claim`. Useful when code was transcribed incorrectly or is from an unknown format.

**Why:** A code like `#00125` (hash + zeros) can never be generated by the current system (0 and 1 are excluded from the alphabet). The pending panel gives staff a code-free fallback.
